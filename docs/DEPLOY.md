# คู่มือ deploy ART CRM

ไฟล์ที่เกี่ยวข้อง: `Dockerfile` (รันที่ไหนก็ได้ที่มี Docker) และ `render.yaml` (Render Blueprint พร้อม persistent disk)

## ก่อนเริ่ม
- สร้างรหัสซิงก์ยาว ๆ สุ่ม เช่น `openssl rand -base64 32` เก็บไว้ในตัวจัดการรหัสผ่านของทีม
- ข้อมูลทั้งหมดอยู่ใน `/data` (ไฟล์ `db.json` และโฟลเดอร์ `backups/`) ต้องมี disk ถาวร

## ขั้นตอนบน Render (แนะนำ)
1. เข้า render.com แล้วเลือก New → Blueprint
2. เชื่อมรีโป `havancrm/havancrm` และเลือกสาขา `claude/art-crm-mobile-sales-b6yzpb`
3. Render อ่าน `render.yaml` และถามค่า `SYNC_TOKEN` ให้ใส่รหัสที่สร้างไว้
4. กด Apply รอจน service เป็น Live แล้วเปิด `https://<ชื่อบริการ>.onrender.com/api/health` ต้องได้ `{"ok":true,...}`

## ขั้นตอนด้วย Docker (VPS หรือแพลตฟอร์มอื่น)
```bash
docker build -t art-crm .
docker run -d --name art-crm -p 8080:8080 \
  -e SYNC_TOKEN='รหัสซิงก์' \
  -v art-crm-data:/data \
  --restart unless-stopped art-crm
```
ต้องอยู่หลัง HTTPS เสมอ เช่น Caddy หรือ Cloudflare Tunnel เพราะกล้องและ GPS ในมือถือใช้ไม่ได้บน http

## ตั้งค่าในแอปบนมือถือ (ทำทีละเครื่อง)
1. เปิดลิงก์ HTTPS บนมือถือ แล้วเพิ่มลงหน้าจอโฮม
2. หลังบ้าน → ตั้งค่า → แท็บ **ระบบ** → ใส่ URL ฐานกลาง (เช่น `https://xxx.onrender.com`) และรหัสซิงก์ → บันทึกและซิงก์ตอนนี้
3. สถานะบน Header ควรเป็น "พร้อมใช้"

## สำรองข้อมูลนอกเครื่อง (ทำทุกสัปดาห์)
- เซิร์ฟเวอร์สำรองไฟล์ `/data/backups/db-วันที่.json` ทุกวัน เก็บ 30 วัน
- คัดลอกโฟลเดอร์นี้ไปเก็บที่อื่น เช่น Google Drive ส่วนตัว
- หรือในแอป: หลังบ้าน → สำรอง / กู้คืน → ดาวน์โหลดไฟล์สำรอง

## ตรวจหลัง deploy
- ทำเช็กลิสต์ใน `docs/PHONE_TEST.md` บนมือถืออย่างน้อย iPhone 1 เครื่องและ Android 1 เครื่อง
- ทดสอบการซิงก์: สร้างลูกค้าบนเครื่อง A แล้วเปิดบนเครื่อง B ต้องเห็นข้อมูลภายในไม่กี่วินาที
- ทดสอบโหมดเครื่องบิน: สร้างออเดอร์ แล้วเปิดอินเทอร์เน็ตกลับมา ออเดอร์ต้องขึ้นในเซิร์ฟเวอร์

## ข้อจำกัดที่ต้องรู้
- ข้อมูลเก็บเป็นไฟล์ JSON เดียว เหมาะกับทีมขนาดเล็กถึงกลาง
- Google Sheet (Apps Script) ซิงก์ได้เฉพาะลูกค้าและออเดอร์ ถ้าต้องการใช้ทุกหมวด ต้องใช้เซิร์ฟเวอร์นี้
