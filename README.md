# ART CRM — ระบบช่วยงานขายบนมือถือ (Local-first)

> ชื่อระบบที่แสดงต่อผู้ใช้คือ **ART CRM** (ชื่อโปรเจกต์ในรีโป `havancrm` เดิม)
> ทำงานจากข้อมูลในเครื่องก่อนเสมอ ใช้ออฟไลน์ได้ และซิงก์กับฐานกลางอัตโนมัติเมื่อมีอินเทอร์เน็ต

## สถาปัตยกรรม (สรุป)
- **Local database** — ข้อมูลทั้งหมดอยู่ในหน่วยความจำ (อ่านทันที) และบันทึกลง IndexedDB ทุกครั้งที่แก้ไข
- **Sync Queue** — ทุกการเปลี่ยนแปลงกลายเป็น operation หนึ่งรายการ (Operation ID, Entity, Record ID, Operation, Payload, Created At, Retry Count)
  ข้อมูลกับ operation ถูกเขียนในธุรกรรมเดียวกัน จึงไม่มีการแก้ไขที่หลุดจากคิว
  ลบ operation เฉพาะเมื่อเซิร์ฟเวอร์ยืนยัน Operation ID นั้นแล้วเท่านั้น ส่งซ้ำได้ปลอดภัย
- **Revision และความขัดแย้ง** — ทุกรายการมี `revision`, `updatedBy`, `updatedAt` เซิร์ฟเวอร์ตรวจ `baseRevision`
  ถ้าแก้ฟิลด์ที่ไม่ชนกันจะรวมให้อัตโนมัติ ถ้าชนกันจะแสดง "ข้อมูลนี้ถูกแก้จากอีกเครื่อง" ให้เลือก
  ดูเวอร์ชัน Cloud / ใช้ข้อมูลของฉัน / ใช้ข้อมูลล่าสุด
- **สำรองข้อมูล** — สำรองอัตโนมัติวันละครั้ง (เก็บ 14 ชุด) สำรองก่อนนำเข้า และก่อนกู้คืนเสมอ · ประวัติการเปลี่ยนแปลง (Audit) เก็บ 5,000 รายการล่าสุด
- **สถานะบน Header** — พร้อมใช้ / รอบันทึก / กำลังบันทึก / ออฟไลน์ / บันทึกไม่สำเร็จ (กด "ลองใหม่" เพื่อส่งเฉพาะรายการที่ไม่สำเร็จ)

## หน้าจอ
| เมนู | ทำอะไรได้ |
|---|---|
| หน้าหลัก | ค้นหาทั้งระบบ (ชื่อ รหัส เบอร์ ที่อยู่ Zone Tag เลขออเดอร์ บิล SKU), งานวันนี้, ลูกค้าถึงรอบ, ยอดขายเดือนนี้ |
| ลูกค้า | ค้นหา/ตัวกรอง/เรียง, การ์ดลูกค้า (โทร นำทาง รับออเดอร์), Customer 360 (ข้อมูล ประวัติซื้อ สินค้าประจำ กิจกรรม), เพิ่ม/แก้ไข, ร้านเป้าหมาย (สถานะ ติดตาม นัด เข้าพบ เสนอสินค้า เปลี่ยนเป็นลูกค้า พร้อมตรวจซ้ำ) |
| รับออเดอร์ | รายการแยกตาม รอส่ง / เปิด LINE แล้ว / เปิดบิลแล้ว, ตัวสร้างออเดอร์ 3 ขั้น (ร้าน → สินค้า → เงื่อนไข/ชำระ) พร้อมร่างที่ไม่หาย, ออเดอร์สำเร็จ, รูปใบสั่งซื้อ (วาดจากข้อมูล), ยกเลิกโดยเก็บประวัติ, แจ้งยอดซื้อ |
| งาน | เลยกำหนด / วันนี้ / ล่วงหน้า / เสร็จแล้ว, รอบลูกค้า (เลยรอบ ถึงรอบ ใกล้ถึงรอบ ปกติ) เลื่อนได้ |
| หลังบ้าน | แผนที่ (พิกัดที่เก็บไว้ ใช้ออฟไลน์ได้), เก็บข้อมูลหน้าร้าน (รูป + GPS + ความแม่นยำ), สินค้า, วิเคราะห์ลูกค้า (CSV/PDF), ยอดขายรวม (ได้ตัวเลข/ไม่ได้ตัวเลข), นำเข้า CSV, ตั้งค่า, สำรอง/กู้คืน, ประวัติการเปลี่ยนแปลง |

**นำเข้าข้อมูล**: รองรับ CSV (ส่งออกจาก Excel เป็น CSV UTF-8) ขั้นตอน เลือกไฟล์ → ตรวจคอลัมน์ → Preview (ซ้ำ/ผิดรูปแบบ/ไม่พบลูกค้า/SKU ไม่พบ) → สำรองอัตโนมัติ → นำเข้า โดยทุกการนำเข้ามี Import ID และบันทึกประวัติ ไฟล์เดิมที่เคยนำเข้าจะมีเครื่องหมายเตือน
ยังไม่รองรับไฟล์ .xlsx โดยตรง ให้บันทึกเป็น CSV ก่อน

**การทดสอบ**: `npm test` (ตรรกะหลัก, การรวมข้อมูล, การซิงก์ของเซิร์ฟเวอร์และ Apps Script)

**ข้อจำกัดของฐานกลาง**: Node.js server รองรับทุกหมวด (ลูกค้า ออเดอร์ ร้านเป้าหมาย งาน กิจกรรม สินค้า)
Apps Script (ตัวเชื่อม Google Sheet เดิม) รองรับเฉพาะ ลูกค้าและออเดอร์ ข้อมูลหมวดอื่นจะรอในคิวในเครื่องจนกว่าจะเปิดใช้งานฝั่งเซิร์ฟเวอร์


แอปช่วยเซลล์ขายบนมือถือ: **ข้อมูลลูกค้า · ออเดอร์ · ยอดขาย** ใช้งานได้ทั้งออนไลน์/ออฟไลน์
ซิงค์ข้อมูลข้ามเครื่องอัตโนมัติ และสำรองข้อมูลได้

## จุดเด่น
- **เร็ว (< 1 วินาที)** — ข้อมูลทั้งหมดอยู่ในหน่วยความจำของเครื่อง (local-first) ไม่ต้องรอเน็ต
  ทดสอบกับลูกค้า 500 ราย + ออเดอร์ 3,000 รายการ: เปิดแต่ละหน้า 8–45 ms, ค้นหา ~15 ms,
  เปิดแอปใหม่ทั้งหมด ~0.23 วินาที (มุมขวาบนแสดงเวลาประมวลผลของแต่ละหน้า)
- **ทำงานออฟไลน์** — เก็บใน IndexedDB + Service Worker ติดตั้งลงหน้าจอโฮมได้เหมือนแอป (PWA)
- **ซิงค์เหมือนข้อมูลในมือถือ** — แก้ไขที่เครื่องไหนก็ได้ ซิงค์อัตโนมัติทุก 60 วินาที / เมื่อแก้ไข /
  เมื่อกลับมาออนไลน์ / เมื่อเปิดแอป ใช้หลัก "ข้อมูลที่แก้ล่าสุดชนะ" ต่อรายการ
- **ฐานข้อมูล Google Sheet** — ดูและแก้ข้อมูลในชีตได้ หรือจะใช้เซิร์ฟเวอร์ Node.js ของตัวเองก็ได้
- **สำรองข้อมูล 3 ชั้น** — (1) ในเครื่อง (2) Google Drive หรือเซิร์ฟเวอร์ สำรองอัตโนมัติรายวันเก็บ 30 ชุด
  (3) ดาวน์โหลดไฟล์ `.json` ไปเก็บเอง และนำเข้ากลับได้


## เชื่อมกับ A-CRM (ฐานข้อมูลจริงใน Google Drive)

ใช้ตัวเชื่อม [`google-apps-script/a-crm/Code.gs`](google-apps-script/a-crm/Code.gs) ซึ่งอ่านข้อมูลจากชีต A-CRM เดิมโดยตรง
ไม่สร้างแท็บใหม่ และไม่ยุ่งกับ Apps Script เดิมที่ผูกกับไฟล์ (เพราะรายงาน APP_INTEGRATION_AUDIT ระบุว่าเป็นของเก่าที่แยกไว้)

| แอปแสดง | อ่านจาก |
|---|---|
| ลูกค้า | `CUSTOMERS` (หาคอลัมน์จากชื่อหัวคอลัมน์ ไม่ใช่ตำแหน่ง และเติมเลข 0 หน้าเบอร์โทรที่หายไป) |
| ยอดขาย / บิล | `BILLS.final_total` เฉพาะ `status = ACTIVE` พร้อมรายการจาก `BILL_ITEMS` (บิลอื่นแสดงเป็น "ไม่นับยอด") |
| ออเดอร์ | `ORDERS` + `ORDER_ITEMS` โดยออเดอร์เดิมที่ไม่มีราคาจะแสดงว่า "ไม่ทราบราคา" และไม่เดาราคา |
| ชื่อสินค้า / หน่วย | `PRODUCTS` |

แอปไม่ใช้ `PURCHASE_SUMMARY` หรือ `DASHBOARD_CACHE` (ตามข้อ 13 ในรายงาน audit) แต่คำนวณยอดซื้อ ความถี่การซื้อ
ลูกค้าที่ควรติดตาม และสินค้าที่ซื้อประจำ จากบิลจริงในเครื่องทุกครั้ง

**ติดตั้ง**
1. เปิด script.google.com → **New project** (สร้างโปรเจกต์ใหม่แยกต่างหาก อย่าใช้สคริปต์ที่ผูกกับไฟล์ A-CRM)
2. วางโค้ดจาก `google-apps-script/a-crm/Code.gs` แล้วแก้ `SYNC_TOKEN` เป็นรหัสลับของทีม
3. เลือกฟังก์ชัน **`testRead`** แล้วกด **Run** → อนุญาตสิทธิ์ → ดูใน Execution log ว่าจำนวนลูกค้า จำนวนบิล และยอด ACTIVE
   ตรงกับที่ควรเป็น (ขั้นตอนนี้อ่านอย่างเดียว ไม่แก้ข้อมูล)
4. **Deploy → New deployment → Web app** ตั้ง Execute as: **Me** และ Who has access: **Anyone** แล้วคัดลอก URL `/exec`
5. ในแอป ไปที่ **ตั้งค่า** → ใส่ URL, รหัส และชื่อผู้ใช้ → **บันทึก & ซิงค์**

**การเขียนข้อมูล (ปิดไว้เป็นค่าเริ่มต้น)**
ระหว่างที่ยังปิดอยู่ ออเดอร์ที่สร้างในแอปจะเก็บไว้ในเครื่อง และแสดงสถานะ "รอซิงค์"
เมื่อทดสอบผ่านแล้ว (ตามข้อ 12 ในรายงาน audit) ให้เปิดได้โดยไม่ต้องแก้โค้ด:
Project Settings → Script Properties → เพิ่ม `WRITE_ENABLED` = `true`
- เขียนได้เฉพาะ**ออเดอร์ใหม่** ลงท้าย `ORDERS` และ `ORDER_ITEMS` (status = `sent`, `last_request_id` = `HAVANCRM-…`)
- ไม่แก้ `CUSTOMERS`, `BILLS` หรือ `BILL_ITEMS`
- ก่อนเขียนครั้งแรกของแต่ละวัน ระบบจะคัดลอกทั้งไฟล์ไปไว้ในโฟลเดอร์ **A-CRM Backups** และไม่ลบไฟล์สำรองเดิม
- ถ้าส่งซ้ำด้วย `order_id` เดิม ระบบจะไม่เพิ่มแถวซ้ำ ส่วนลูกค้าที่ไม่มีรหัสใน `CUSTOMERS` ระบบจะไม่รับออเดอร์
- แนะนำให้ทดสอบกับ**สำเนา**ของ A-CRM ก่อน โดยเปลี่ยน `SPREADSHEET_ID` ไปที่ไฟล์สำเนา

**ความเร็ว** (วัดกับข้อมูลจำลองขนาดเท่าของจริง: ลูกค้า 1,135 ราย บิล 6,300 ใบ รายการสินค้า 18,830 รายการ)
- ซิงค์ครั้งแรก ประมาณ 1.2 วินาที (ไม่รวมเวลาที่ Google ใช้อ่านชีตจริง ซึ่งอาจเพิ่มอีกหลายวินาที)
- เปิดแต่ละหน้า 7–45 ms, ค้นหาลูกค้า 2 ms, เปิดแอปใหม่ 0.3 วินาที
- ซิงค์ครั้งถัดไปส่งเฉพาะแถวที่ `updated_at` เปลี่ยนหลังจุดซิงค์ล่าสุด (ย้อนไปเผื่อ 10 นาที) และเก็บในเครื่องทันที
  ไม่ดึงทั้งชีตใหม่ทุกครั้งที่มีการแก้ไขในชีต
- ดึงข้อมูลทั้งหมดใหม่วันละครั้ง เพื่อให้แถวที่ถูกลบออกจากชีตหายจากแอปด้วย
- ข้อจำกัด: แถวที่ไม่มีวันที่แก้ไขเลย (`updated_at`, `created_at`, `order_date`) จะไปถึงมือถือในการซิงค์เต็มรอบประจำวัน

## เชื่อมฐานข้อมูล Google Sheet (แนะนำ — ไม่ต้องมีเซิร์ฟเวอร์)

ข้อมูลลูกค้าและออเดอร์จะอยู่ใน Google Sheet ของคุณ เปิดดู กรอง ทำ Pivot หรือแก้ไขในชีตได้เลย
และทุกการแก้ไขจะซิงค์ไปที่มือถือทุกเครื่อง

**1. สร้างชีตและติดตั้งสคริปต์**
1. สร้าง Google Sheet ใหม่ (sheets.new)
2. เมนู **ส่วนขยาย (Extensions) → Apps Script** ลบโค้ดเดิม แล้ววางโค้ดจาก [`google-apps-script/Code.gs`](google-apps-script/Code.gs)
3. แก้บรรทัด `const SYNC_TOKEN = '...'` เป็นรหัสลับของทีม แล้วกด 💾 บันทึก
4. เลือกฟังก์ชัน **`setup`** แล้วกด **Run** และกดอนุญาตสิทธิ์ (Advanced → Go to … → Allow)
   ระบบจะสร้างชีต **ลูกค้า** และ **ออเดอร์** และตั้งเวลาสำรองข้อมูลอัตโนมัติทุกวันตอนตี 2

**2. เปิดให้แอปเชื่อมต่อ**
1. กด **Deploy → New deployment →** ⚙️ เลือก **Web app**
2. ตั้ง **Execute as: Me** และ **Who has access: Anyone** แล้วกด Deploy
3. คัดลอก **Web app URL** (ลงท้ายด้วย `/exec`)

> ถ้าแก้โค้ดภายหลัง ต้องไปที่ Deploy → Manage deployments → ✏️ → Version: **New version** แล้วกด Deploy
> โดย URL จะยังเหมือนเดิม

**3. ตั้งค่าในแอป**
เปิดแอป → **ตั้งค่า** → วาง URL `/exec` และรหัส `SYNC_TOKEN` → **บันทึก & ซิงค์ตอนนี้**
ทำแบบเดียวกันในทุกเครื่องของทีม

### แก้ไขข้อมูลในชีต
- **เพิ่มลูกค้า:** พิมพ์แถวใหม่ต่อท้าย (ใส่แค่ชื่อก็ได้) ระบบจะใส่รหัสให้เองตอนซิงค์ครั้งถัดไป
- **เพิ่มออเดอร์:** ใส่ วันที่ (`2026-10-11` หรือ `11/10/2569`) ชื่อลูกค้า และรายการสินค้าบรรทัดละ 1 รายการ
  ในรูปแบบ `ชื่อสินค้า × จำนวน @ ราคา` (ขึ้นบรรทัดใหม่ในเซลล์ใช้ Ctrl/⌘+Enter)
  ถ้ายังไม่มีชื่อลูกค้านี้ ระบบจะสร้างลูกค้าใหม่ให้ ส่วนยอดสุทธิคำนวณให้อัตโนมัติ
- **ลบ:** ให้ติ๊กช่อง **ลบแล้ว** และอย่าลบทั้งแถว (ถ้าลบแถว มือถือที่มีข้อมูลอยู่จะไม่รู้ว่าถูกลบ)
- ถ้าต้องการเปลี่ยนลูกค้าของออเดอร์ ให้แก้ในแอป
- อย่าแก้หรือย้ายคอลัมน์ที่ซ่อนอยู่ (id, updatedAt…) ถ้าต้องการเพิ่มคอลัมน์ของตัวเอง ให้เพิ่มทางขวาสุด
- มือถือจะเห็นการแก้ไขจากชีตภายในประมาณ 3 นาที หรือทันทีเมื่อกดปุ่มซิงค์

### สำรองข้อมูล
- อัตโนมัติทุกวัน: คัดลอกทั้งไฟล์ไปไว้ในโฟลเดอร์ **HavanCRM Backups** บน Google Drive โดยเก็บไว้ 30 ชุดล่าสุด
- สำรองทันทีได้จากเมนู **HavanCRM → สำรองข้อมูลตอนนี้** ในชีต หรือจากปุ่มในหน้าตั้งค่าของแอป
- Google Sheet มี **ประวัติเวอร์ชัน** (File → Version history) ให้ย้อนกลับได้อีกชั้นหนึ่ง

### วางแอปให้มือถือเปิดได้ (ต้องเป็น HTTPS)
อัปโหลดโฟลเดอร์ `app/` ไปยังโฮสติ้งเว็บแบบ static ตัวไหนก็ได้ (ใช้ฟรี) เช่น
**Netlify Drop** (ลากโฟลเดอร์ `app` ไปวางที่ app.netlify.com/drop), **Cloudflare Pages** หรือ **GitHub Pages**
จากนั้นเปิดลิงก์นั้นบนมือถือ แล้วเลือก **เพิ่มลงหน้าจอโฮม**

> ความเร็ว: แอปอ่านและเขียนข้อมูลในเครื่องเสมอ หน้าจอจึงตอบสนองในระดับมิลลิวินาทีเหมือนเดิม
> ส่วนการซิงค์กับ Google Sheet ทำงานเบื้องหลัง ใช้เวลาประมาณ 1–3 วินาที โดยไม่ทำให้แอปช้า
> Google Sheet เหมาะกับข้อมูลระดับหลักหมื่นแถว ถ้ามากกว่านั้นแนะนำให้ใช้เซิร์ฟเวอร์ด้านล่าง

## ทางเลือก: เซิร์ฟเวอร์ของตัวเอง (Node.js)
ต้องการ Node.js 18+ (ไม่มี dependency ภายนอก) เซิร์ฟเวอร์นี้ทำหน้าที่ทั้งเปิดแอปให้มือถือและซิงค์ข้อมูล

```bash
SYNC_TOKEN=รหัสลับของทีม PORT=8080 npm start
```
1. เปิด `https://<ที่อยู่เซิร์ฟเวอร์>` บนมือถือ แล้วเลือก **เพิ่มลงหน้าจอโฮม**
2. ไปที่ **ตั้งค่า** แล้วใส่ที่อยู่เซิร์ฟเวอร์และรหัสซิงค์

ข้อมูลอยู่ใน `server/data/` (เปลี่ยนที่เก็บได้ด้วย `DATA_DIR`) และระบบสำรองเป็นไฟล์ไว้ทุกวัน 30 วัน
ถ้าจะใช้งานจริง ควรวางไว้หลัง HTTPS (Caddy / Nginx / Cloudflare Tunnel)

## โครงสร้าง
```
app/      ART CRM (PWA, ไม่ต้อง build)
  core.js        ตรรกะล้วน (สถิติ รอบลูกค้า ค้นหา ตรวจซ้ำ รวมข้อมูล นำเข้า CSV) ไม่แตะ DOM หรือเครือข่าย
  db.js          ข้อมูลในเครื่อง: หน่วยความจำ + IndexedDB, Sync Queue, Audit, สำรอง, ความขัดแย้ง
  sync.js        ซิงค์จากคิว: ลบ operation เฉพาะที่ยืนยันแล้ว, ลองใหม่พร้อม backoff
  derived.js     ข้อมูลที่คำนวณจากข้อมูลในเครื่อง (memoized ตามเวอร์ชันข้อมูล)
  ui.js          ไอคอน, ตัวจัดการเหตุการณ์แบบรวมจุดเดียว, bottom sheet, toast
  app.js         router เดียว, header สถานะ, แท็บล่าง, สร้างหน้าสำหรับความขัดแย้ง
  views/         หน้าจอ: home, customers, orders, work, backstage
  sw.js          แคชให้เปิดได้ทันทีและออฟไลน์
google-apps-script/a-crm/   ตัวเชื่อม A-CRM (อ่าน CUSTOMERS/BILLS/ORDERS เดิม)
google-apps-script/Code.gs   ฐานข้อมูล Google Sheet แบบสร้างชีตใหม่ (วางใน Apps Script)
server/   เซิร์ฟเวอร์ซิงค์ + สำรองข้อมูล (Node.js ล้วน)
test/     เทสต์การรวมข้อมูลของทั้ง 2 แบบ (`npm test`)
```

## API
Google Apps Script: `POST <url>/exec` ส่ง body เป็น `text/plain` ที่มีข้อมูล `{ token, action: "sync" | "backup", since, changes }`

Node.js:
- `POST /api/sync` `{ since, changes: { customers: [], orders: [], leads: [], tasks: [], activities: [], products: [] } }`
  → `{ cursor, changes, acceptedIds, conflicts, supports }` (`acceptedIds` = opId ที่บันทึกแล้วต่อหมวด, `conflicts` = ฉบับบนเซิร์ฟเวอร์ที่ชนกัน)
- `POST /api/backup` สร้างสแนปช็อตทันที · `GET /api/health`
- ทุก request ต้องมี `Authorization: Bearer <SYNC_TOKEN>` เมื่อกำหนด `SYNC_TOKEN`
